変更されたファイルを確認し、CLAUDE.local.mdのコミットガイドラインに従って適切な粒度でステージングしてください。

以下の手順で実行してください:

1. `git status`と`git diff`を並列実行して、変更されたファイルを確認
2. 変更内容を分析して、論理的なまとまりごとにグループ化
3. 適切な粒度でステージングを提案:
   - 1コミット1目的の原則に従う
   - 実装とテストは別のグループとして扱う
   - 依存関係を考慮した順序を提案（例：スキーマ → ビジネスロジック → API → UI）
4. ユーザーに確認を求めてからステージングを実行

グループ化の基準:
- **機能単位**: 同じ機能に関連する変更をまとめる
- **層単位**: データベース層、ビジネスロジック層、API層、UI層など
- **ファイル種別**: 実装ファイルとテストファイルは別グループ
- **除外**: CLAUDE.mdや.env.exampleは基本的に除外

注意事項:
- 変更がない場合は、その旨を伝えてください
- 複数の目的が混在している場合は、どのようにグループ化したかを説明してください
- 各グループに適切なコミットメッセージの例を提案してください
