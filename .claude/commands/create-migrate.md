スキーマファイルの変更を自動検知して、適切なマイグレーション名を提案し、マイグレーションファイルを生成してください。

## 実行手順

### 1. スキーマ変更の検知

以下を並列実行して、変更されたスキーマを検知してください:

- `git diff HEAD~5 apps/core/db/schemas/`で過去5コミット分のスキーマファイルの差分を確認
- `git status apps/core/db/schemas/`で新規作成・変更されたファイルを確認
- `ls apps/core/db/schemas/`でスキーマファイル一覧を確認

### 2. 変更内容の分析

検知した変更から、以下を判断してください:

- **新規テーブル**: 新しい`*Table.ts`ファイルが作成された → `create_テーブル名`
- **カラム追加**: 既存テーブルに新しいカラムが追加された → `add_テーブル名_カラム名`
- **カラム削除**: カラムが削除された → `drop_テーブル名_カラム名`
- **カラム変更**: カラムの型や制約が変更された → `alter_テーブル名_カラム名`
- **複数の変更**: 複数の変更がある場合は、最も重要な変更を選択

### 3. マイグレーション名の提案

CLAUDE.mdの命名規則に従って、2-3個の候補を提案してください:

**命名規則:**
- テーブル名はスネークケースに変換（例: `userNamesTable` → `user_names`）
- 操作_テーブル名_カラム名の形式
- 関数/トリガーの場合は`create_function_名前`や`create_trigger_名前`

**提案フォーマット:**
```
以下のマイグレーション名を提案します:

1. create_user_names（推奨）
2. add_user_names_table
3. create_user_names_table

番号を入力して選択するか、カスタム名を入力してください（デフォルト: 1）:
```

### 4. ユーザーの選択を待つ

**重要**: マイグレーション名の候補を提示した後、**必ずユーザーの入力を待ってください**。

- ユーザーが番号（1, 2, 3）を入力した場合: 対応する候補を使用
- ユーザーがカスタム名を入力した場合: その名前を使用
- ユーザーが何も入力しない（Enterのみ）場合: 推奨（1番）を使用

### 5. マイグレーションの生成

選択された名前で以下を実行:

1. `cd apps/core`
2. `bun run db:generate --name 選択された名前`
3. 生成されたマイグレーションファイルを読み込んで内容を表示
4. ファイルパスと次のステップ（`bun run db:migrate`）を案内

## 特殊なケース

- **変更がない場合**: 「スキーマファイルに変更が検出されませんでした」と報告
- **カスタムSQL**: `.sql`ファイルを直接作成する場合は、その旨を検知して報告
- **複雑な変更**: 複数テーブルにまたがる変更は、それぞれ個別のマイグレーションを推奨

## 注意事項

- 必ずユーザーに候補を提示してから実行してください
- 生成後、マイグレーションファイルの内容を確認して表示してください
- ステージングされていない変更がある場合は、先にコミットを推奨してください
